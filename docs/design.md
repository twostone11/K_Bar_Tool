# K_Bar_Tool 技术方案

状态：待评审（尚未开发）
日期：2026-11-18

## 1. 目标

提供一个"凭记忆默画K线"的训练工具，用于训练盘感。用户先观察一段真实美股日K线，图表隐藏后，用鼠标凭记忆把它画出来，系统将画作与原图对比并打分。

### 已确认的范围

| 项目 | 决定 |
| --- | --- |
| 市场 | 美股 |
| K线周期 | 日线 |
| 价格轴 | 固定刻度（后续可加"无刻度"难度） |
| 输入方式 | 鼠标 |
| 数据来源 | 后续由用户提供，先用本地样例数据 |

### 非目标（首版不做）

- 分钟/小时周期
- 实盘或模拟交易、涨跌预测
- 账号系统、云端同步、多人排行
- 技术指标（均线、MACD 等）

## 2. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 启动快，配置少 |
| 语言 | TypeScript | 评分与数据结构较多，类型可减少出错 |
| 渲染 | 原生 Canvas 2D | "画K线"需要完全自定义的交互，现成图表库不支持 |
| UI | 原生 DOM，不引入框架 | 页面简单，只有三个界面状态 |
| 存储 | `localStorage` | 只存成绩历史，无需后端 |
| 测试 | Vitest | 仅用于评分和数据抽样的纯函数 |
| 部署 | 静态文件，可放 GitHub Pages | 无服务器成本 |

纯前端，无后端。数据源接入后如果需要隐藏 API Key，再单独加一个轻量代理（见第 9 节）。

## 3. 用户流程

状态机共四个状态：

```
IDLE → MEMORIZE → DRAW → RESULT → IDLE
```

1. **IDLE（设置）**：选择K线根数 N（默认 20）、记忆时长 T（默认 30 秒）、是否显示成交量，点击开始。
2. **MEMORIZE（记忆）**：显示原图和倒计时，可点"我记住了"提前结束。
3. **DRAW（默画）**：原图隐藏，保留空白画布、价格刻度和日期位置。用户逐根画K线，点"提交"进入评分。
4. **RESULT（结果）**：原图与用户画作叠加，显示总分和每根K线的误差。可选择"再来一题"或"重画本题"。

## 4. 题目生成

从数据中随机抽取一段连续的 N 根日K线。

- **输入数据**：每只股票一份日线，字段为 `date, open, high, low, close, volume`。
- **抽样**：随机选股票，再随机选起点，保证窗口内无缺失数据。
- **价格轴范围**：取窗口内最低价与最高价，上下各留 10% 边距，再向"整齐刻度"取整（如 0.5、1、5）。刻度在记忆和默画阶段保持一致。
- **复权**：使用前复权价格，避免除权造成的缺口。

## 5. 绘制交互

画布坐标与价格、K线序号互相映射：每根K线占一个等宽的列，价格与纵坐标线性对应。

**单根K线的画法**

1. 在某一列内按下鼠标，竖向拖动到松开，得到影线的 `high` 和 `low`（按住的起点与终点，取较大与较小者）。
2. 随后在同一列内点击两次：第一次设定 `open`，第二次设定 `close`，并受 `low ≤ open, close ≤ high` 约束。
3. 实体颜色按 `close >= open` 判定涨跌（颜色方案见第 8 节）。

**编辑**

- 拖动影线端点或实体边缘可以调整价格。
- 右键或快捷键删除当前列。
- 撤销/重做（`Ctrl+Z` / `Ctrl+Shift+Z`）。
- 价格吸附：默认吸附到 0.01 美元的整数倍，可在设置中关闭。

**为什么这样设计**：一次拖动画影线、两次点击画实体，每根K线 3 次操作。N=20 时约 60 次操作，仍可在记忆窗口之后的合理时间内完成。待原型验证后再根据手感调整。

## 6. 评分算法

输入为原图 `A` 与用户画作 `U`，各含 N 根K线。未画的K线按 0 分计。

### 6.1 单根K线得分

对 `open, high, low, close` 四个价格，计算归一化误差：

```
err_p = |A_p - U_p| / (axis_max - axis_min)
```

用价格轴量程归一，使不同价位的股票可以比较。单根得分：

```
candle_score = 100 × (1 - clamp(mean(err_open, err_high, err_low, err_close) / E_max, 0, 1))
```

`E_max` 是"完全错误"的误差阈值，初始值取 0.25（即平均偏差达到量程的 25% 得 0 分），可调。

涨跌方向不一致时，该根得分额外乘以 0.7（方向错误是盘感层面的错误）。

### 6.2 整体形态得分

比较相邻K线之间的收盘价变化方向与幅度排序，避免整体平移但形态正确的画作被过度惩罚。方法：对 `close` 序列计算相邻差分，求原图与画作差分序列的 Pearson 相关系数，映射到 0 到 100。

### 6.3 总分

```
total = 0.7 × mean(candle_score) + 0.3 × shape_score
```

权重和 `E_max` 都是初始值，需要用真实使用来校准，评审时请确认是否合理。

### 6.4 结果展示

- 总分、形态分、平均每根K线分。
- 误差最大的 3 根K线高亮。
- 叠加视图：原图用实心，用户画作用半透明描边。

│  ├─ storage/

评分、抽样、坐标映射都是不依赖浏览器的纯函数，便于单独测试。

## 8. 视觉约定

- 美股惯例：**绿涨红跌**。如果你更习惯 A 股的红涨绿跌，在 `theme.ts` 中切换，设置里提供开关。
- 深色背景，减少长时间训练的视觉疲劳。
- 画布按设备像素比缩放，保证高分屏清晰。

## 9. 数据接入（待你提供）

首版定义统一接口，其余不变：

```ts
interface Candle { date: string; open: number; high: number; low: number; close: number; volume: number }
interface DataSource { listSymbols(): Promise<string[]>; getDaily(symbol: string): Promise<Candle[]> }
```

候选方案，供你选数据源时参考：

| 方案 | 优点 | 注意点 |
| --- | --- | --- |
| 本地 CSV/JSON 文件 | 无依赖，离线可用 | 需要自己更新数据 |
| Yahoo Finance 导出文件 | 免费，覆盖广 | 非官方接口，稳定性与条款需自行确认 |
| Alpha Vantage / Polygon / Tiingo 等 API | 稳定，有文档 | 需要 API Key，免费额度有限，需要代理保护 Key |

建议首版用本地文件，题库放在 `public/data/`，保存数十只股票各 5 年以上的日线即可。

## 11. 风险与待确认事项

**风险**

- 鼠标画 3 步操作的手感是否顺手，需要 M2 原型验证，可能要调整为"拖动实体"等方案。
- 评分阈值和权重是经验初值，需要用真实练习数据校准。
- 数据源的授权与稳定性由你选定的来源决定。

**待你确认**

1. 默认K线根数 20、记忆 30 秒是否合适？
2. 颜色采用绿涨红跌还是红涨绿跌？
3. 是否需要显示成交量？（目前设为可选，默认关闭）
4. 评分的权重（逐根 70%、形态 30%）是否符合你的预期？
5. 首版数据准备用本地文件吗？如果是，大概需要覆盖哪些股票？
